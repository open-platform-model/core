## Context

See proposal.md, Why. The page dialect is `STYLE.md` "Site Pages" in the workspace root; opmodel.dev's `site/scripts/lint-sources.sh` enforces it, and its build fails on a broken link or a missing page.

Files this change touches in `src/`: `component.cue`, `module_instance.cue`, `transformer.cue`, `platform.cue`, `catalog.cue`, `schemas.cue`, `types.cue` (doc comments only) and `src/INDEX.md` (regenerated). No construct in `.tasks/spec-tracked.txt` changes, no SPEC.md section moves, no construct is newly tracked, and no definition changes its closedness, defaults or required fields.

## Goals / Non-Goals

**Goals:**

- One generated entry per public definition, in the owner's fixed order, stating only what the source proves.
- Output that is byte-stable, passes the site's dialect lint and builds on opmodel.dev.
- A check in `task check` and CI that fails when `src/` and the committed pages disagree.

**Non-Goals:**

- Projecting `SPEC.md`. It stays the contributor-facing specification.
- Evaluating the schema. Every fact is read off the AST.
- A "served by" part: nothing in core relates a definition to what serves it, so the part is never written.
- Editing opmodel.dev. Its placeholder change is separate.

## Decisions

### Inclusion

Every exported (`#`-prefixed) top-level definition in a non-fixture file of `src/` (fixtures are `*_pins.cue`) is either on a page or excluded in `tools/refgen/groups.go` with a reason; hidden (`_`) definitions are never candidates. Included: 40 definitions on eight pages. Excluded: the seven `*Map` shorthands, `#KebabToPascal` and `#KebabToCamel` (string helpers), `#DiscoverSecrets` and `#GroupSecrets` (steps of `#AutoSecrets`), the four content-hash and immutable-name helpers transformers use, and `#BundleFQNType`, which types a `#Bundle` core does not define. A reference to an excluded definition is followed through to the included ones it names, so `#Component`'s `#resources: #ResourceMap` still lists `#Resource` under Uses.

### Entry shape

| Part | Source |
| --- | --- |
| Summary | First sentence of the cleaned doc comment, its leading `#Name:` label dropped |
| At a glance | File, module path, shape read off the AST (closed or open struct, map, string constraint, disjunction), the `kind` value, embedded definitions, Uses and Used by |
| Spec | The definition as written, formatted by `cue/format` with four-space indent; only doc and same-line comments kept, cleaned; a derived `T & {...}` value over 40 lines with comprehensions is shown as `T` with a note (only `#Platform.#contracts` today) |
| Example | `Example:` and `Usage:` segments of the doc comment |
| Notes | The rest of the doc comment |
| Enforcement | Rules read off constraints, each tagged as enforced by CUE: closedness, required (`!`) fields (with an `if` clause's condition), a field pinned to `true` beside the expression it tests, a field declared twice with two scalar expressions, and a string constraint's pattern and rune bounds |

Parts are bold labels rather than headings, so a page's table of contents lists definitions only. A regular expression goes in a `text` block, never inline: the site lint reads `](` in inline code as a link.

### Filtering

Rationale blocks (`// WHY ...`) are separated from the doc comment by a blank line, so the parser attaches them as non-doc groups and the generator drops every non-doc group. Inside the doc comment it removes enhancement citations (`0010:D37`, with lead-ins such as "enhancement" or "per"), `See SPEC.md § N.M` pointers and experiment references, then tidies the punctuation the removal leaves. A paragraph the rules leave unchanged keeps its line breaks; a changed one is re-wrapped. Where a comment still read badly, the comment was fixed in `src/` instead of adding a rule.

### Markers and authored text

The generated block sits between `<!-- generated by task docs:reference from the CUE definitions in src/; DO NOT EDIT -->` and `<!-- end generated -->`, the same markers as the cli's command reference. The generator owns the front matter and the block and keeps any text an author writes between the front matter and the opening marker or after the closing one. A file in the directory the generator does not write fails the check and is removed on regeneration.

### Links

Root-absolute with a trailing slash and a fragment: `/docs/reference/definitions/<page>/#<name>`, where the fragment is the definition name lower-cased without `#`, the ID Hugo gives the heading `## #Name`. Verified against a real build: all 40 fragments match a heading ID.

## Research & Decisions

### Comment attachment

**Context**: The filter depends on how `cue/parser` attaches comment groups.
**Explored**: A probe over `src/module.cue` with `parser.ParseComments`.
**Decision**: Keep only groups with `Doc` or `Line` set.
**Rationale**: A doc comment is the group ending directly above its field (`Doc: true`); a `// WHY` group separated by a blank line attaches to the previous field as a trailing, non-doc group. Dropping it removed the blank line `cue/format` printed before the next field's doc comment; setting the relative position of that comment's first line to a new section restores it.

### Required-field wording

**Context**: Whether "required" means refused by `cue vet`.
**Explored**: `cue vet` and `cue vet -c` (v0.17.1) on a value missing a `!` field.
**Decision**: The rule says a value is incomplete until each required field is set, and CUE names the missing one when it needs a complete value.
**Rationale**: Plain `cue vet` reports only "some instances are incomplete"; `-c` names `field is required but not present`. Closedness is reported by plain `cue vet` (`field not allowed`).

### Site build

**Context**: The pages must build on opmodel.dev, whose placeholder at the same path refused source pages.
**Explored**: The opmodel.dev worktree that lets a `placeholder: true` page yield to a source page.
**Decision**: Verified with `OPM_VERSIONS=v1.0=/src OPM_SRC_CORE=<worktree> task build` and `task lint:sources` there.
**Rationale**: Build, dialect lint, page set, sidebar order and link checks all pass; the Reference sidebar lists the eight pages in weight order.
