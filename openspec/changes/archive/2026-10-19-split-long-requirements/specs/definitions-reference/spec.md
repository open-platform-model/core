## MODIFIED Requirements

### Requirement: The definitions reference is generated into the docs bundle

The definitions reference SHALL be generated by docs-kit's `cue-definitions` extractor from `src/*.cue` when core's docs bundle is built, at `reference/definitions/` with the URLs it has today (`/docs/reference/definitions/<page>/#<anchor>`). Every exported top-level definition SHALL be on exactly one page of `docs-kit.cue`'s `pages` or in its `exclude` with a reason; a normal build SHALL fail, listing every definition that is unplaced, placed twice or unknown.

#### Scenario: A new definition is placed

- **WHEN** a contributor adds `#Foo` to `src/types.cue` and lists it in the `definitions` of the `names-paths-and-versions` page in `docs-kit.cue`
- **THEN** `task docs:bundle` writes an entry for `#Foo` on `reference/definitions/names-paths-and-versions.md` and a row for it in `reference/definitions/_index.md`

#### Scenario: A new definition is left out

- **WHEN** a contributor adds `#Foo` to `src/types.cue` and neither places nor excludes it
- **THEN** `task docs:bundle:check` fails, naming `#Foo`, its file and `docs-kit.cue`

#### Scenario: Pins files are skipped

- **WHEN** the extractor reads `src/*.cue` and a file matches `*_pins.cue`
- **THEN** the file SHALL be skipped
