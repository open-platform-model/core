## REMOVED Requirements

### Requirement: Every public definition has one generated entry
**Reason**: `tools/refgen` is deleted; docs-kit's `cue-definitions` extractor generates the pages inside core's docs bundle from the inclusion list in `docs-kit.cue` (docs-kit C17).
**Migration**: Place or exclude a new definition in `docs-kit.cue` instead of `tools/refgen/groups.go`; `task docs:bundle` replaces `task docs:reference`.

### Requirement: An entry states only what its source proves
**Reason**: The entry shape is docs-kit's (C17 D5), ported from refgen with a recorded parity run; core no longer renders entries.
**Migration**: None for authors; a rendering fix is a docs-kit change that reaches core at its next `.opm-docs-version` bump.

### Requirement: Contributor-only text never reaches a page
**Reason**: docs-kit's doc-comment rules and its default `strip` citation policy apply the same filtering (C6, "Doc-comment rules").
**Migration**: None; `// WHY` blocks and citations stay where they are.

### Requirement: The committed reference is never stale
**Reason**: Nothing generated is committed any more, so nothing can be stale; the bundle is built from `src/` at the commit or tag it documents.
**Migration**: `task docs:bundle:check` and the `Docs / check` job replace `task docs:reference:check` and its CI step.

### Requirement: Pages follow the site page dialect
**Reason**: docs-kit lints every bundle in bundle mode before it publishes and again when the site pulls it (C11).
**Migration**: None.

## ADDED Requirements

### Requirement: The definitions reference is generated into the docs bundle

The definitions reference SHALL be generated by docs-kit's `cue-definitions` extractor from `src/*.cue` (files matching `*_pins.cue` skipped) when core's docs bundle is built, at `reference/definitions/` with the URLs it has today (`/docs/reference/definitions/<page>/#<anchor>`). Every exported top-level definition SHALL be on exactly one page of `docs-kit.cue`'s `pages` or in its `exclude` with a reason; a normal build SHALL fail, listing every definition that is unplaced, placed twice or unknown.

#### Scenario: A new definition is placed

- **WHEN** a contributor adds `#Foo` to `src/types.cue` and lists it in the `definitions` of the `names-paths-and-versions` page in `docs-kit.cue`
- **THEN** `task docs:bundle` writes an entry for `#Foo` on `reference/definitions/names-paths-and-versions.md` and a row for it in `reference/definitions/_index.md`

#### Scenario: A new definition is left out

- **WHEN** a contributor adds `#Foo` to `src/types.cue` and neither places nor excludes it
- **THEN** `task docs:bundle:check` fails, naming `#Foo`, its file and `docs-kit.cue`

### Requirement: No generated reference page is committed

The repository SHALL NOT commit pages under `docs/site/reference/definitions/`, and SHALL carry no generator of its own for them. A committed page at a path the extractor writes SHALL fail the bundle build.

#### Scenario: A stray generated page is refused

- **WHEN** a contributor commits `docs/site/reference/definitions/components.md`
- **THEN** `task docs:bundle:check` fails, naming the colliding page
